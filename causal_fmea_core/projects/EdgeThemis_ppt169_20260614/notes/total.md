# 01_cover

今天我们来介绍 EdgeThemis——一个基于形式化验证的因果推理引擎。本系统基于微软研究院关于 LLM 因果推理缺陷的发现，以及 Reflexion 框架的自反思思想，首次将工业 FMEA 风险评估与 LLM 因果推理结合，通过 Rust 形式化验证引擎实现微秒级逻辑拦截。目标是在 8GB 显存的边缘硬件上实现工业级因果推理。

# 02_motivation

我们的工作建立在两篇核心论文之上。第一篇是微软研究院的工作，发表于 ICLR 2024，他们证明了大模型根本不懂因果，只是"因果复读机"——记住训练语料中的词汇共现，遇到抽象变量就彻底瞎蒙。第二篇是 Reflexion，发表于 NeurIPS 2023，提出了 Actor-Evaluator-Reflection 的语言强化学习闭环。但 Reflexion 的 Evaluator 是软性的，无法保证数学绝对正确性。EdgeThemis 的核心创新就是用 Rust 图论算子取代这个软性评估器，将确定性拉满。

# 03_problem

因果推理在医疗诊断、工业故障分析等领域至关重要。LLM 虽然能从文本中提取因果关系，但存在三个结构性缺陷。第一是因果幻觉，LLM 可能生成无中生有的因果链。第二是环路隐患，有向图中可能出现循环，违反 DAG 基本约束。第三是风险盲区，提取出的因果边没有量化风险评估。现有方法缺少对 LLM 因果推理输出的形式化验证闭环。

# 04_contributions

我们的工作有三个核心贡献。第一个是混合架构，LLM 通过 JSON Schema 强制输出结构化因果图，然后交给 Rust 形式化验证引擎进行环路检测和 d-分离验证。第二个是 FMEA 风险量化，将工业工程中的失效模式与影响分析融入因果图的每条边。第三个是自反思纠错闭环，验证失败时拦截报告反馈给 LLM，最多五轮自动修正。

# 05_architecture

来看系统架构的完整流水线。文本输入首先经过 LLM 生成器，基于 Qwen 2.5 模型和 JSON Schema 约束提取结构化因果图。然后进入 Rust 形式化验证引擎，同时进行 Kahn 环路检测、Bayesian Ball d-分离验证和 FMEA RPN 风险评估。如果检测到违规，拦截报告反馈给 LLM 重新生成；如果通过验证，交给 Reflector LLM 进行常识判断，最终输出经过验证的因果图和 FMEA 报告。

# 06_generator

Generator 节点是系统的起点。它接收自然语言文本，通过 JSON Schema 约束 LLM 强制输出结构化的 CausalEdge 数据结构，每条边包含 cause、effect、S、O、D 五个字段和推理过程。我们使用 Qwen 2.5 三 B 参数模型，四比特量化，通过 llama-server 的 OpenAI 兼容 API 调用。Pydantic 模型在 Python 层做最终校验，确保输出格式可被 Rust 引擎直接解析。

# 07_interning

字符串驻留池是 Rust 引擎的基础设施。LLM 输出的节点名是字符串，但 Rust 图算法操作的是整数 ID。我们用 IndexSet 配合 Arc 和 Mutex 实现了一个线程安全的驻留池，同一节点名只存一次，查找复杂度 O(1)。Python 通过 FFI 的 inject_edges 方法将边列表传入 Rust，Rust 端自动完成字符串到整数的映射。底层的 CompactCausalGraph 用一维扁平邻接表存储，CPU 缓存友好。

# 08_kahn_cycle

Kahn 算法是第一道防线——检测因果图中是否存在环路。算法流程是：先统计每个节点的入度，将入度为零的节点推入队列，然后像剥洋葱一样层层拆解。如果成功拆解的节点数等于总节点数，说明无环；否则有环，触发熔断。复杂度 O(V+E)，非常高效。此外，在边注入阶段就会拦截自环边，从源头杜绝无意义的因果回路。

# 09_bayesian_ball

Bayesian Ball 算法是 d-分离验证的核心。它的关键创新是给 BFS 搜索的每个状态附加一个"方向"标记——Up 表示逆箭头找原因，Down 表示顺箭头找结果。算法有四条状态转移规则。规则一：向上走到未观测节点时两个方向都允许。规则二：向上走到已观测节点时两个方向都阻断。规则三：向下走到未观测节点时只允许继续向下。规则四：向下走到已观测节点时只允许向上——这是对撞结构的激活条件。如果贝叶斯球成功从起点 X 滚到了终点 Y，说明存在非法连通路径。

# 10_case_chain_obs

第一种情况：链式结构，中间节点 M 已被观测。比如药物导致血压降低，血压降低导致头晕缓解。如果我们已知血压确实降低了，那么在"血压已降"的前提下，用药对头晕缓解无额外预测力。球从用药出发，向上走到血压降低节点，因为 M 已观测，规则二触发，两个方向都被阻断，球卡死在 M。路径被物理切断，X 和 Y 被 d-分离。

# 11_case_chain_unobs

第二种情况：链式结构，中间节点 M 未被观测。比如用药导致病情好转，病情好转导致恢复运动。如果我们不知道病情是否好转，球从用药出发，向下走到病情好转，因为 M 未观测，规则三触发，只允许继续向下，球到达恢复运动。这是唯一合法的因果通路——Chain 结构本身就是真实的因果链，连通是正确的。

# 12_case_fork_obs

第三种情况：共因结构，共同原因 M 已被观测。比如暴雨同时导致手术推迟和空气湿度高。如果我们已确认当天确实下暴雨，在"已知暴雨"的前提下，手术推迟和湿度高之间无虚假相关性。球从手术推迟出发，向上走到暴雨节点，因为 M 已观测，规则二触发，球卡死在 M。后门被堵死，这就是后门准则的工程实现。

# 13_case_fork_unobs

第四种情况：共因结构，共同原因 M 未被观测。同样的暴雨场景，但这次没记录天气。暴雨同时导致了手术推迟和湿度高，LLM 可能误以为手术推迟导致湿度高。球从手术推迟出发，向上走到暴雨，因为 M 未观测，规则一允许两个方向都走，球向下走到湿度高。球到达 Y，后门大开。这是 LLM 最常见的错误——忘记控制混杂变量。

# 14_case_collider_obs

第五种情况：对撞结构，对撞节点 M 已被观测——这是最反直觉的。比如业务能力和人脉关系都能让人成为合伙人。如果我们已知此人是合伙人，发现他业务能力不行，就能推断他靠关系。这就是 explaining away 效应。球从业务能力出发，向下走到合伙人，因为 M 已观测，规则四触发，只允许向上走，球通过逆箭头摸到了人脉关系。观测对撞节点反而激活了虚假路径。

# 15_case_collider_unobs

第六种情况：对撞结构，对撞节点 M 未被观测。同样的合伙人场景，但不知道此人是否是合伙人。业务能力和人脉关系本来就是两码事，互不影响。球从业务能力出发，向下走到合伙人节点，因为 M 未观测，规则三只允许向下，但对撞节点没有向下的边，球卡死在 Z。对撞节点的出厂设置就是天然阻断——不翻垃圾桶就安全。

# 16_fmea

FMEA 是工业工程中广泛使用的风险评估方法。我们将其引入因果推理，每条因果边携带三个维度的评分：严重度 S、发生概率 O、检测难度 D，取值都是一到十。风险优先数 RPN 等于一百乘 S 加十乘 O 加 D。当 RPN 超过五百或者 S 大于等于九时，系统触发高风险告警。这是 FMEA 工业方法论首次与 LLM 因果推理结合。

# 17_reflection

自反思闭环是我们的核心创新之一。当 Rust 验证引擎检测到违规时，拦截报告会反馈给 LLM 生成器进行修正。第一轮可能包含环路，第二轮可能有 d-分离违反，第三轮全部验证通过。系统设置了五轮熔断机制，防止无限循环。每次成功生成的图谱被记录为最佳图谱，即使触发熔断也返回历史最佳结果。

# 18_experiment

实验配置方面，我们使用 Qwen 2.5 三 B 参数模型，四比特量化，通过 llama-server 本地部署，运行在八 GB 显存的 RTX 4060 上。三组消融对比分别是：Config A 纯 LLM 无验证，Config B 加上 Schema 约束和 Rust 验证，Config C 在此基础上加入自反思闭环。

# 19_ablation

消融实验的结果非常清晰。Config A 纯 LLM 可能产生环路，综合质量最低。Config B 加入 Rust 验证后，环路被拦截，FMEA 标注有了，但 d-分离问题只能检测不能修正。Config C 完整系统不仅检测 d-分离违反，还能通过自反思闭环自动修正，综合评分达到九十五分。

# 20_case_study

以医院感染场景为例。左边 Config A 的输出存在环路，没有 FMEA 标注。经过三轮自反思修正后，右边 Config C 的输出环路消除，每条边都标注了 FMEA RPN 风险值，高风险边自动告警。

# 21_conclusion

总结来说，EdgeThemis 证明了混合架构在提升因果推理可验证性方面的有效性。我们首次将 FMEA 与 LLM 因果推理结合，Bayesian Ball d-分离和 Kahn 环路检测实现了轻量级形式化验证，自反思闭环显著提升了因果图的逻辑一致性。
