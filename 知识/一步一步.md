 1.战役一——字符串驻留池（String Interning Pool）设计
 -


我们在选择跨语言数据传输策略时，如果大模型在 Python 侧疯狂吐出因果图节点（如 "冷却系统异常", "反应堆熔毁"），如果把这些沉重的字符串（String）全部深拷贝扔给 Rust， 4060 剩下的 2GB 显存和内存会被海量的内存碎片瞬间撑爆（OOM）。

所以坚决抵制字符串！建立全局字典（驻留池）。 Python 传进字符串，Rust 没收它，并扔回一个极度轻量的整数编号（如 0, 1）。以后的 FMEA 拦截和图论计算，全在 CPU 寄存器里用光速的整数对比完成！

1.Cargo.toml 里引入了 indexmap::IndexSet
-
    Bash
    # 压入 PyO3 (并开启 Python 3.10 ABI 扩展模块特性)
    cargo add pyo3@0.20.2 --features extension-module,abi3-py310

    # 压入驻留池神器 indexmap
    cargo add indexmap@2.1.0

2.在src/lib.rs中修改代码
-

    use pyo3::prelude::*;
    use indexmap::IndexSet;
    use std::sync::{Arc, Mutex};   // Arc（原子引用计数指针）和 Mutex（互斥锁）

    #[pyclass]
    pub struct CausalParadigmEngine {   // 声明 Rust 结构体可以暴露给 Python 使用
        interner: Arc<Mutex<IndexSet<String>>>,  // 类型为 Arc<Mutex<IndexSet<String>>>，即线程安全、可共享的字符串集合
    }

    #[pymethods]  // 声明这是实现的方法
    impl CausalParadigmEngine {     // 实现 CausalParadigmEngine 的方法，并暴露给 Python
        #[new]  // 指定为 Python 构造函数
        pub fn new() -> Self {  // 返回一个新的 CausalParadigmEngine 实例 就像Py中的 __init__ 方法一样
            println!("⚡ [CausalForge] 正在初始化 EdgeThemis 引擎...");
            println!("⚡ [CausalForge] 正在开辟底层字符串驻留池...");
            CausalParadigmEngine {
                interner: Arc::new(Mutex::new(IndexSet::new())),  // 初始化为一个空的 IndexSet，并用 Arc 和 Mutex 包裹，保证线程安全和可共享
            }
        }

        /// 任务 1：注册节点
        pub fn register_node(&self, node_name: String) -> PyResult<usize> {
            // 你的逻辑 1：极其粗暴地拿锁，并声明为可变 (mut)
            let mut pool = self.interner.lock().unwrap();
            
            // 你的逻辑 2：插入数据，并用 .0 提取第一个元素 (ID)  insert_full 返回 (index, bool),取下标
            let id = pool.insert_full(node_name).0;
            
            Ok(id)
        }

        /// 任务 2：反向查询
        pub fn get_node_name(&self, node_id: usize) -> PyResult<Option<String>> {
            // 拿锁（只读，所以不需要 mut）
            let pool = self.interner.lock().unwrap();
            
            // 获取引用，并克隆一份 String 扔回给 Python 把内部数据“拷贝”出来，安全返回给 Python
            Ok(pool.get_index(node_id).cloned())
        }
    }

    #[pymodule]  // 声明为 Python 模块初始化函数
    fn causal_fmea_core(_py: Python, m: &PyModule) -> PyResult<()> {
        m.add_class::<CausalParadigmEngine>()?;
        Ok(())
    }

2.战役二：极速 FMEA 量化算子
-
用 Rust 徒手搓出这个“计算总风险值 (RPN)”的公式

    RPN = S * O * D

    S (Severity, 严重度)：后果有多惨？

    例子：报废一个灯泡，S=2；反应堆爆炸炸死人，S=10。

    O (Occurrence, 频发度)：这事儿有多容易发生？

    例子：百年一遇的陨石砸中机房，O=1；每天都漏水的破管子，O=9。

    D (Detection, 探测度)：⚠️ 注意，这个值是反直觉的！ 它代表“在灾难发生前，系统有多难发现它”。

    例子：有高精度警报器秒级拦截，D=1；隐蔽的底层内存泄漏（神不知鬼不觉），D=9。

为了防止极端情况发生

    采用“严重度绝对偏置算法”：RPN = (100 * S) + (10 * O) + D


在fmea_evaluator.rs中添加类声明及其实现方法：
-

    // 实现FMEA算法 SOD
    use pyo3::prelude::*;

    #[pyclass]
    #[derive(Clone, Copy, Debug)]
    pub struct FmeaScore {
        #[pyo3(get, set)] pub s: u32, // 让 s、o、d 这三个字段在 Python 侧可以直接读写（即 obj.s、obj.s = 1）。
        #[pyo3(get, set)] pub o: u32,
        #[pyo3(get, set)] pub d: u32,
    }

    #[pymethods]
    impl FmeaScore {
        #[new]
        pub fn new(s: u32, o: u32, d: u32) -> Self {
            FmeaScore { s, o, d }
        }

        /// 核心任务：用 Rust 确立裁判法则
        pub fn calculate_rpn(&self) -> u32 {
            // 隐式返回法则：这行不加分号，直接将其作为 u32 结果扔给 Python
            (100 * self.s) + (10 * self.o) + self.d
        }
    }


然后在src/lib.rs里引入这个新文件，并把FmeaScore注册到Python模块里：

    // 提取武器：把 FmeaScore 拉到当前作用域

并在最后module初始化函数里注册这个类：

        Ok(())

3.战役三：物理死神拦截 (The Reaper) 回收显存空间的类与doro函数
-

Python 的垃圾回收机制（GC）很懒，会等内存快炸了才去清理，容易造成OOM

但是在rust中，只要变量离开作用域的那一微秒，编译器会强行唤醒一个叫 Drop 的底层特化守卫（死神），立刻挥下镰刀，把内存砸得粉碎，绝不拖泥带水！

我们要把这个死神，无缝挂载到 Python 的生命周期上！
-

用 Arc（原子引用计数）把死神包装起来，然后把它作为 CausalParadigmEngine 的一个内部器官（_reaper）塞进去。这在底层的物理意义是：只要引擎实例（Engine）活着，引用计数就是 1，死神就沉睡；一旦 Python 宿主把引擎销毁，引用计数瞬间归零，死神立刻苏醒，强制执行 drop 函数里的“清除内存”动作！

在纯 Rust 的世界里，变量不用了，生命周期结束，Rust 会自动把它清理得干干净净，根本不需要我们手动去写 Drop。

那为什么在 EdgeThemis 里非要写？
因为我们现在的系统，横跨了三界：Python（宿主） -> Rust（桥梁） -> C++（llama.cpp 显卡引擎）。

Python 侧的慵懒： 当你在 Python 里写下 del engine 时，Python 的垃圾回收器 (GC) 会把 Python 包装壳给碾碎。

Rust 侧的自动清理： PyO3 感知到壳碎了，立刻通知 Rust：“宿主死了，你也可以死了。” Rust 收到指令，会自动把 Arc、Mutex 和 IndexSet 的内存释放掉。这一步，无需我们操心。

💥 C++ 侧的致命盲区： 但是！我们在底层其实调用了 C++ 的 llama.cpp 引擎霸占着 4060 的显存（VRAM）。Rust 的编译器再牛，也看不见 C++ 分配的内存！如果我们就这么死了，那 4.3GB 的显存就会变成永远无法回收的“僵尸显存（Memory Leak）”。

这就是为什么我们要手动实现 Drop！
手动实现 Drop，相当于给这个 Rust 结构体写下了一段“临终遗言”。
当 Rust 准备销毁这个结构体的前一微秒，它会强行停下来，执行我们在 drop(&mut self) 里写的代码（比如打印日志，或者执行极其危险的 unsafe { llama_free(...) }）。执行完这句遗言后，它才会咽气。

 Kahn 算法 (拓扑排序)纯迭代！统计所有节点的“入度”（被几根线指着）。每次只剥离入度为 0 的边缘节点。✅ 绝对的降维打击。 不依赖递归，在扁平的一维数组（Vec）里极速狂飙，时间复杂度死死钉在 $O(V+E)$！

    // 文件：src/algorithms.rs
    use crate::dag::CompactCausalGraph;

    pub struct CausalAlgorithms;

    impl CausalAlgorithms {
        /// 核心任务 1：Kahn 算法拦截逻辑死循环
        /// 返回值：如果图是健康的（无环），返回 true；如果侦测到死循环幻觉，返回 false 触发拦截！
        pub fn kahn_cycle_detect(graph: &CompactCausalGraph) -> bool {
            let n = graph.node_count;
            if n == 0 { return true; }

            // 物理动作 1：在堆内存开辟入度统计表，全部置零
            let mut in_degree = vec![0; n];
            
            // 物理动作 2：全面扫描图谱，统计每个节点的入度（被指向的次数）
            for from_node in 0..n {
                if from_node < graph.adjacency_list.len() {
                    for &to_node in &graph.adjacency_list[from_node] {
                        in_degree[to_node] += 1;
                    }
                }
            }

            // 物理动作 3：把所有入度为 0 的“自由节点”（比如案卷的初始证据）推入处理队列
            let mut zero_in_degree_queue = Vec::new();
            for i in 0..n {
                if in_degree[i] == 0 {
                    zero_in_degree_queue.push(i);
                }
            }

            // 物理动作 4：像剥洋葱一样，层层拆解因果图
            let mut processed_nodes = 0;
            while let Some(node) = zero_in_degree_queue.pop() {
                processed_nodes += 1;
                
                if node < graph.adjacency_list.len() {
                    for &neighbor in &graph.adjacency_list[node] {
                        // 砍断连接的边
                        in_degree[neighbor] -= 1;
                        // 如果下家也没有依赖了，进入自由队列
                        if in_degree[neighbor] == 0 {
                            zero_in_degree_queue.push(neighbor);
                        }
                    }
                }
            }

            // 终极物理审判：如果成功拆解的节点数等于总节点数，说明没有死扣；否则，绝对有环！
            processed_nodes == n
        }
    }

    pub fn is_d_separated(
            graph: &CompactCausalGraph, 
            x: usize, 
            y: usize, 
            observed: &HashSet<usize>
        ) -> bool {
            let n = graph.node_count;
            if n == 0 || x == y { return false; }

            // 🌟 你的战术执行：榨干 CPU！在寄存器里动态开辟内存，临时反转图谱！
            let mut rev_adj = vec![Vec::new(); n];
            for u in 0..n {
                if u < graph.adjacency_list.len() {
                    for &v in &graph.adjacency_list[u] {
                        rev_adj[v].push(u); // 逆向记录：v 的上游是 u
                    }
                }
            }

            // 物理准备：找出所有观察节点及其祖先（用于对撞因子的激活判断）
            let mut ancestors_of_observed = HashSet::new();
            let mut q = VecDeque::new();
            for &obs in observed {
                q.push_back(obs);
                ancestors_of_observed.insert(obs);
            }
            while let Some(node) = q.pop_front() {
                for &parent in &rev_adj[node] {
                    if ancestors_of_observed.insert(parent) {
                        q.push_back(parent);
                    }
                }
            }

            // 贝叶斯球开始滚动！状态元组：(当前节点, 运动方向)
            // 方向：true 代表往子节点滚 (Down)，false 代表往父节点滚 (Up)
            let mut queue = VecDeque::new();
            let mut visited = HashSet::new();

            queue.push_back((x, false)); 
            visited.insert((x, false));

            while let Some((curr, is_down)) = queue.pop_front() {
                // 如果贝叶斯球成功滚到了终点，说明没有被 d-分离（存在连通的幻觉路径）
                if curr == y { return false; }

                // 规则 1：顺着箭头往子节点走 (Down)
                if !is_down && !observed.contains(&curr) {
                    for &child in &graph.adjacency_list[curr] {
                        if visited.insert((child, true)) { queue.push_back((child, true)); }
                    }
                } else if is_down {
                    // 如果是 Collider（对撞），只有它或它的孙子被观察到时，路径才通！
                    if ancestors_of_observed.contains(&curr) {
                        for &parent in &rev_adj[curr] {
                            if visited.insert((parent, false)) { queue.push_back((parent, false)); }
                        }
                    }
                }

                // 规则 2：逆着箭头往父节点走 (Up)
                if !is_down && !observed.contains(&curr) {
                    for &parent in &rev_adj[curr] {
                        if visited.insert((parent, false)) { queue.push_back((parent, false)); }
                    }
                } else if is_down && !observed.contains(&curr) {
                    // Chain 或 Confounder
                    for &child in &graph.adjacency_list[curr] {
                        if visited.insert((child, true)) { queue.push_back((child, true)); }
                    }
                }
            }

            // 贝叶斯球滚遍了全图都没碰到 y，说明路径被成功物理切断！(d-separated = true)
            true
        }

**这是全场最变态的逻辑（伯克森悖论）**：对于对撞结构 `A -> C <- B`，如果 `C` 被观测到了（在 `observed` 里），这条路反而**通了**！更恶心的是，如果 `C` 没被观测到，但 `C` 的某个“孙子节点”被观测到了，这条路也算通！
所以，我们必须提前顺着逆向图往上爬，把所有被观测节点的“祖宗十八代”全都扔进一个集合里，备用。

关于“孙子节点”： 它是指 $C \rightarrow \text{孙子}$。也就是说，如果 $C$ 指向 $D$，哪怕 $C$ 没有被观测到，只要 $D$（孙子节点）被观测到了，对撞结构 $A \rightarrow C \leftarrow B$ 也会被瞬间打通！

这就是为什么在代码的战前准备里，我们需要把所有观测节点的祖宗全部塞进 ancestors_of_observed 集合里！ 只要贝叶斯球滚到了 $C$，一查发现它的孙子 $D$ 在这个集合里，球就会毫不犹豫地穿过去！

### ⚙️ 第三部分：贝叶斯球的运动状态机

真正的核心在于这颗球的状态。我们用了一个元组 `(curr, is_down)` 来记录球当前的物理状态。

* `curr`：球现在停在哪个节点上。
* `is_down`（极其重要）：球是**怎么来到这里的？**
* `is_down = true`：球是**顺着箭头 (Down)** 滚过来的（`上一节点 -> curr`）。
* `is_down = false`：球是**逆着箭头 (Up)** 滚过来的（`上一节点 <- curr`）。



---

### ⚙️ 第四部分：四大物理碰撞法则

在 `while let Some((curr, is_down)) = queue.pop_front()` 的大循环里，代码被严格切分成了两大块，对应四种真实的因果拓扑碰撞法则：

#### 场景一：球是“逆着箭头 (Up)”滚到当前节点的 (`!is_down`)

这意味着物理轨迹目前长这样：`历史节点 <- curr`。

* **法则 1 (Chain 反向)：球继续逆着箭头往上找。**
* **代码：** `if !is_down && !observed.contains(&curr) { 找 parent }`
* **逻辑：** 只要当前节点没被观测，球可以顺滑地穿过去，形成 `历史节点 <- curr <- 新节点`。


* **法则 2 (Confounder 共因)：球在顶点反弹，顺着箭头往下滚！**
* **代码：** `if !is_down && !observed.contains(&curr) { 找 child }`
* **逻辑：** 只要当前节点没被观测，它可以作为共因，把两条路连起来，形成 `历史节点 <- curr -> 新节点`。
* **死神拦截：** 如果这个共因 `curr` 被观测到了（比如明确排除了某个混淆证据），这两个 `if` 都进不去，球当场被物理阻断！



#### 场景二：球是“顺着箭头 (Down)”滚到当前节点的 (`is_down`)

这意味着物理轨迹目前长这样：`历史节点 -> curr`。

* **法则 3 (Chain 正向)：球继续顺着箭头往下滚。**
* **代码：** `else if is_down && !observed.contains(&curr) { 找 child }`
* **逻辑：** 最普通的逻辑链推导。只要 `curr` 没被观测定死，就能继续推导 `历史节点 -> curr -> 新节点`。


* **法则 4 (Collider 对撞因子)：反直觉的触底反弹！**
* **代码：** `else if is_down { if ancestors_of_observed.contains(&curr) { 找 parent } }`
* **逻辑：** 球现在处于坑底 `历史节点 -> curr`。如果要往上爬形成 `历史节点 -> curr <- 新节点`，**只有当 `curr` 或者它的后代被观测到时（存在于我们战前准备的那个集合里），这个通道才会诡异地打开！**



### 🏁 最终判决

这颗球就在这四条冰冷的法则中疯狂裂变、滚动。
如果任何一颗分身球撞到了终点 `y`，立刻 `return false;`（拦截失败，路是通的）。
如果队列抽干了，球全都卡死在了路上，说明大模型吐出的这两个节点之间没有任何逻辑关联，绝对是幻觉。此时高傲地 `return true;`（d-分离成功，斩断幻觉）！
