Dockerfile文件：
---

    # .devcontainer/Dockerfile
    # 从12.1.0升级到 CUDA 12.4.1，彻底镇压 half 精度编译歧义问题
    FROM nvidia/cuda:12.4.1-devel-ubuntu22.04

    ENV DEBIAN_FRONTEND=noninteractive

    RUN apt-get update && apt-get install -y \
        build-essential cmake git curl wget sudo \
        python3 python3-pip python3-dev \
        && rm -rf /var/lib/apt/lists/*

    ARG USERNAME=hehe
    ARG USER_UID=1000
    ARG USER_GID=$USER_UID

    RUN groupadd --gid $USER_GID $USERNAME \
        && useradd --uid $USER_UID --gid $USER_GID -m -s /bin/bash $USERNAME \
        && echo "$USERNAME ALL=(root) NOPASSWD:ALL" > /etc/sudoers.d/$USERNAME \
        && chmod 0440 /etc/sudoers.d/$USERNAME

    USER $USERNAME
    WORKDIR /home/$USERNAME

    RUN curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
    ENV PATH="/home/${USERNAME}/.cargo/bin:${PATH}"
    ENV PYO3_PYTHON=/usr/bin/python3

    ARG CUDA_ARCH=89

    # --- 终极物理防弹衣：双重变量齐下，彻底镇压链接器 ---
    # 1. 编译期直接依赖寻址
    ENV LIBRARY_PATH=/usr/local/cuda/lib64/stubs:$LIBRARY_PATH
    # 2. 编译期传递依赖验证 & 运行期寻址
    ENV LD_LIBRARY_PATH=/usr/local/cuda/lib64/stubs:$LD_LIBRARY_PATH
    # 3. 欺骗系统，伪造驱动
    RUN sudo ln -s /usr/local/cuda/lib64/stubs/libcuda.so /usr/local/cuda/lib64/stubs/libcuda.so.1 || true

    # 执行编译（斩断网络代理，多核全开，保留全部官方测试玩具！）
    RUN sudo mkdir -p /opt/llama.cpp \
        && sudo chown -R $USERNAME:$USERNAME /opt \
        && export http_proxy="" && export https_proxy="" && export HTTP_PROXY="" && export HTTPS_PROXY="" \
        && git clone https://github.com/ggml-org/llama.cpp.git /opt/llama.cpp \
        && cd /opt/llama.cpp \
        && cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=${CUDA_ARCH} \
        && cmake --build build --config Release -j $(nproc)

验证阶段
-

1. 验证 Rust 跨语言桥梁脚手架 (maturin)：

        Bash
        maturin --version
预期体感：秒出 maturin 1.x.x。这证明 Python 和 Rust 之间的跨语言打包工具已经就位，这是我们后续干翻 Python GIL 锁的资本。

----------------------------------------------------------
2. 验证 C++ 核心库是否真的链接到了真显卡：

        Bash
        ldd /opt/llama.cpp/build/bin/llama-cli | grep cuda
预期体感：必须看到 libcuda.so.1 => /usr/lib/wsl/lib/libcuda.so.1 或者类似的真实驱动路径！这证明我们在 docker run 阶段，已经成功扒下了之前编译时的“假驱动”伪装，真正接管了 4060 的物理硬件！

但是问题来了，libcuda.so.1 => /usr/local/cuda/lib64/stubs/libcuda.so.1
这证明虽然你的 4060 硬件已经挂载进来了，但你的 llama-cli 玩具，此时此刻依然瞎了眼，认贼作父，连着那个不能做任何算力推理的“假驱动（stubs）”！

接下来执行：
下一步动作（极其暴力的物理切除）：
在终端里直接一枪干掉这个假驱动的软链接！执行：

        Bash
        sudo rm /usr/local/cuda/lib64/stubs/libcuda.so.1

        删掉之后，再次执行：

        Bash
        ldd /opt/llama.cpp/build/bin/llama-cli | grep cuda


        会在终端中找到：libcuda.so.1 => /usr/lib/x86_64-linux-gnu/libcuda.so.1

        └── lib.rs      # Rust 源代码模板，包含 PyO3 模块初始化代码
